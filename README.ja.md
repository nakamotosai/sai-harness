# sai-harness

> Claude / agent デリバリーシステムの公開ノート：報告の骨格 · チェックリストは常に最後

![sai-harness：Claude / agent デリバリーシステムの公開ノート](assets/readme/hero.svg)

## 一言で言うと

公式 Claude Code はプログラム可能な agent の殻。その上に個人デリバリーシステムを育てた：複数ステップのタスクは検索・仕様・実行・証拠検証・行動進化を強制的に通す；五つの常駐サブエージェントで意思決定・品質検査・外部検索・画像認識・リモートを分担；知識は四つのライブラリに分け、長文は現行版を一つだけ；複雑な作業はデフォルトで分担してから集約し、複雑になったら会議にはしない；人への報告は固定の五つの表、表の外に散文を置かない。クライアントの魔改造なし。全部 `CLAUDE.md`、skills、agents、hooks、MCP。

このリポジトリはこの説明と能力マップが中心。プライベート設定、鍵、内網アドレスはここには出てこない。

## 何が違うのか

公式の素のインストールでもコードを書き、git を回し、MCP に繋ぎ、hooks を書き、サブエージェントを開ける。  
二つ目の Claude Code を発明したわけではない。違いは規律、分業、記憶の分け方、複雑なタスクをどう切り分けてまとめ直すか、そして「自分ではできたと思う」が完了扱いになるかどうか。

### 原則

1. **マップは短く、プロセスは深く。** トップルールはルーティングだけ；厚いプロセスは skill へ。
2. **完了は証拠で判断。** ディスクの状態、コマンド結果、検証レシートが決める。
3. **サブエージェントは専門。** 選定する者は品質検査をしない、品質検査する者は計画を決めない。
4. **記憶は分離。** 短期の失敗、プロジェクト、視覚、長文、混ぜない。
5. **エラーは完全に絶つ。** 文言を変えるだけでは足りない、再発したら失敗するチェックを残す。
6. **既存を探してから手作り。** 検索で見つかる車輪は、デフォルトではゼロから発明しない。
7. **人には同僚のように。** 先に結果とあなたが感じる変化を；自己検証はクリック・更新・聴く・見るであって、スクリプトの壁を投げつけられることではない。
8. **デフォルトで分担、デフォルトで会議しない。** 独立した調査/実装は分担し結果をメインに戻す；本当の相互議論や同質の大量バッチだけ昇格する。
9. **計画はパッケージ。** 効果を出すなら完全な計画を；「やる」と言ったらパッケージ全体、メニュー式の半端ではない。

### 早見：デフォルト vs 私

| | デフォルト Claude Code | この構成 |

| 位置づけ | 強力なコーディング会話アシスタント | 個人デリバリーシステム |
| 記憶 | その会話 + 自動ノート | 四つのライブラリ + 偏好ルール + 長文バージョン |
| 複数ステップタスク | 催促しないと緩い | 検索 → 仕様 → 実行 → 検証 → 書き戻し |
| 複雑な並列 | 一人で抱え込むか乱発会議 | デフォルトで分担してメインに戻す；集約を落盤；再生可能なパイプライン |

## 中核メソッド

### アーキテクチャ

```
あなた
 └─ メイン制御セッション（マップを読み、割り当て、締め、書き戻す）
     ├─ ルール：短いマップ + 偏好リスト + 記憶インデックス
     ├─ リズム：複数ステップタスクはパイプライン強制
     ├─ オーケストレーション：デフォルトは分担してメインへ；本当の相互議論 / 同質の大量バッチだけ昇格
     ├─ サブエージェント：計画 / 品質検査 / 外部検索 / 画像認識 / リモート
     ├─ 領域スキル：フロントエンド、メディア、リモート、知識、進化……
     ├─ ハードゲート：危険アクション遮断、圧縮後の規律再注入、任意の通知
     ├─ 外部接続：知識ベース検索、ネット検索、ドキュメント、メッセージブリッジ
     └─ 四つのライブラリ：失敗 / プロジェクト台帳 / テーマ+デモ / 長文ウィキ
```

### デリバリーパイプライン：五ステップ

一ステップを超える作業は、デフォルトで全線を走る：

1. コンテキストを検索（先に失敗帳、次に長文/外网）
2. ゴールと受入を書く（何をもって完了とするか、やらないことも明示）
3. 高リスクだけ人に聞く（コア削除、金/アカウント、トップルール変更）
4. 実行（分担すべきなら分担し、結果はメイン制御に戻す）
5. 通るまで検証（証拠不足ならやり直し）
6. 記憶に書き戻し、**骨格五表**で報告

失敗したら**二重修正**：今回の産物を直すだけでなく、根本原因（ルールまたは検査）も直す。ファイルだけ直して完了宣言しても、完工ではない。

### 配線：五つの常駐サブエージェント

| 役割 | 追加された能力 |
|------|----------------|
| **計画審判** | 論理・安全・実現性の三関門；一票でも否決なら強行できない |
| **完了品質検査** | 「変更したと主張したこと」をディスクと照合；自己申告の合格は無効 |
| **外部検索取証** | 検索と証拠圧縮に専念；生死を決めず、最終稿を奪わない |
| **スクリーンショット識図** | UI 受入はテキストのみ返す、メインセッションが大画像で溢れない |
| **リモートプローブ** | SSH/大ログを短い証拠に圧縮してから戻る |

誰がやるべきかは誰がやる。メイン制御は一人で全役を演じない。

### オーケストレーション（グラフ思考、殻を変えない）

ネットの agent graph の話は、核心はだいたいこう：一人で抱え込まない、割くべきなら割く、割いたら集約する、途切れたらどこで詰まっているか見える。  
外の別のグラフエンジンに乗り換えたわけではない。相変わらず Claude Code の skill / サブエージェント / 任意の team·workflow の上に規律を溶接している：

| ルール | 意味 |
|------|------|
| **デフォルトは分担してメインへ** | 独立した取証・実装はサブエージェント；結果はメインセッションに戻して集約 |
| **本当の相互議論だけ会議** | 複数役割が互いに弁証する必要があるときだけ小隊へ昇格；簡単な作業の会議強制は禁止 |
| **同質の大量バッチだけパイプライン** | 多数の同一ステップだけバッチ編成にする；集約産物を強制 |
| **段階ごとに依存を明記** | 複雑な計画は誰が誰に依存し、何を読み、何を出すかを書き、途中で詰まりが見える |
| **多経路は必ず集約** | 複数経路が並行に終わったら集約ファイル必須、頭の中だけで組み立ててはいけない |
| **完了時に短いパイプライン記録** | 誰が登場したか、何回差し戻されたか、一行ずつ再生可能 |
| **長プロジェクトだけブレークポイント** | 数日にわたる長い作業だけ複数のブレークポイントファイル；日常の短い作業は不要 |
| **昇格すべきでなければしない** | 簡単な問題やオープン研究に無理にハードトポロジー：センサーが止める |

あなたの体感：複雑なタスクはより安定するが、「最先端に見せる」ために毎回の会話を戦闘室にはしない。

### 記憶：四つのライブラリ

デフォルトのアシスタントの記憶は一つの鍋に溶けやすい。四つに分け、それぞれ自分の持ち場を管理：

| ライブラリ | 何をする | 実際の使い道 |
|----|--------|----------|
| **失敗帳** | 短い教訓、再発指紋、罠 | 同じ類の作業はまず過去の帳を調べる |
| **プロジェクト台帳** | プロジェクト横断の台帳、優先度 | 冒頭で全体として何をすべきか分かる |
| **テーマライブラリ** | UI 規格、再利用可能なデモ | フロントはゼロからスタイルを推測しない；実験はライブラリに昇格できる |
| **ウィキ知識ベース** | 長文の真実源；話題ごとに現行版を一つだけ | 調査/マニュアルに live、旧版は履歴へ、ゴミは回収へ |

偏好は別のリストがある：どう報告するか、どう決めるか、絶対にやらないこと。エージェントが自分で書き戻し、「メモしておきますか」とは聞かない。

### 報告の骨格（人に話す）

各メッセージを作業指示として扱う。会話はデフォルトで真人の同僚のように振る舞う。  
「例えば A、B」と言えば、まず同類を広げる。深く研究してほしいときはメカニズムとコピー可能な手順を渡す。

デリバリーや完了のときは、**表だけ出す、表の外にまとめ文や末尾の繰り返しは置かない**。固定の五ブロック、順序は次の通り：

| ブロック | 何を書く |
|----|--------|
| **1 一行の結果** | できた / 結論は / どこで詰まっている |
| **2 人ことばの説明** | 何が起きたか、どう扱ったか、やらなかったことを明示 |
| **3 効果と自己検証** | あなたが感じること + あなたがどう自分で確認するか（合体；自己検証はクリック/更新/聴く/見るであって、コマンドの壁ではない） |
| **4 次の一手の判断** | 閉じられるなら閉じてよいと言う；足りなければ完全な次の一手を書く；指示とずれていればまず計画を直す |
| **5 チェックリスト** | エージェント自身の検証チェック（品質検査 / 失敗書き戻し / 記憶 / 長文など）、「分かりました」をチェックさせるものではない |

必要なときだけブロックを追加：どこを開くか、全文はどこか、これを選べ、リスク、拍板など。  
計画チケットは三文だけ：**このままやる / 計画を変える / まず動かさない**。「やる」= パッケージ全体、多選スーパーマーケットに分解しない。

トップルールのマップはこの五ブロックだけ固定；表の細部と追加ブロックのリストは偏好ファイルに置き、マップが手引きに膨らまないようにする。

### その他の能力面

**外部検索**

| 段階 | 何をする |
|----|--------|
| **浅い** | 小さな問題、少ないラウンド、本文を本当に読む |
| **深い** | 大きな研究、多ラウンド多角度、反証が必要、結論は長文に |
| **効果裁判** | 新しい文が古い文を覆すときだけ置き換え；書き終えたからといって唯一の真実を名乗れない |

新しい実装、新しい計画、詰まって補招が必要：デフォルトで既存を探す（オープンソースとコミュニティの重み大）、適合するものがなければ自作し、何を検索したか・なぜ使わなかったかを書く。

**安全**

危険な git、破壊的削除、鍵面の直接読み：システムレベルで遮断。  
クレデンシャルは暗号化管理で、鍵をそのまま会話に流し込まない。  
長い会話が圧縮された後、重要な鉄則は再注入される。  
ターン終了時に個人通知チャネルへ送れる；画面の前にいなくても結果サマリーを見られる。

**リモートとセッション横断**

リモートメッセージと定期タスクは触手を広げるもので、第二の主脳ではない。  
具体的なタスクがない冒頭は、まずプロジェクトレーダーを報告し、暇話をしない。  
長プロジェクトには立ち上げ、引き継ぎ、アーカイブの骨格があり、セッションをまたいでブレークポイントから再開できる。  
本機ブラウザの複数アカウントはレーンを混ぜない；ブリッジが切れたら直してから作業する。

**設計、デモ、メディア**

ランディングページ、プロジェクト内 UI、設計規格、logo はそれぞれの入口を通り、混ぜて適当にいじらない。  
工程図はデフォルトで一画面の図 + 一画面の説明。  
トポロジーがないときは情報カード。  
選定パネルとチューニング実験は本当にテーマライブラリに入れて初めて収蔵。  
視覚受入はスクリーンショット識図頼み；一画面ダッシュボードに大片の空き床を許さない。  
生図、ローカル超解像、ナレーション、成片、動画分析に固定入口がある。

**自己進化**

| 能力 | 意味 |
|------|------|
| 連続エラーで進化 | 同じ類の愚行が再発したら、ルールを変え、謝るだけではない |
| 警告の昇格 | 明確に警告/怒ったら、最高規格で走り、その場で誤魔化さない |
| 再発失敗センサー | ルールが文字で書かれただけでは終わらない；再発したら失敗するチェックを残す |
| harness 変更の対照 | トップルール / skill / hooks を触る前にベースラインを走らせ、変えた後に数字を見る |
| ルール執筆に門 | トップルールに執筆規範があり、散文のゴミ捨て場に積み上げるのを禁止 |
| skill に入口 | 新建や大改はメタフローを通り、手作りで納品するのを禁止 |

## このリポジトリ

**あるもの**

- この公開能力説明
- 能力の全体マップ（`docs/harness-map.png`、16:9）
- テーマ hero（`assets/readme/hero.svg`）
- 以後、脱敏テンプレート、コピー可能なチェックリストを補うかも

**ないもの、そして置かないもの**

- API Key、Cookie、Token、アカウントプール
- 内網アドレス、プライベートホスト名、顧客情報
- 私の本番環境に直接接続できる設定
- 「インストールしたら私と同じ強さ」という魔法スクリプト

規律はコピーできる。あなた自身の罠と筋肉はコピーできない。

## クイックスタート

他人の人生をクローンする必要はない。公式の拡張点の上に積み上げる：

| 歩 | 何をする |
|----|--------|
| 1 | 短く硬いグローバル `CLAUDE.md` を書く：鉄則 + ルーティング表；厚いプロセスは詰め込まない |
| 2 | 繰り返しプロセスを skill に分ける（デリバリー、外部検索、進化 各一つあれば始められる） |
| 3 | 一二個の読み取り専用サブエージェントを足す：品質検査、外部検索 |
| 4 | hook で最も恐れる誤操作を溶接して塞ぐ |
| 5 | 知識は少なくとも分ける：短い教訓 vs 長文 |
| 6 | 完了には確認可能な証拠が必要；自己申告の完了は無効 |
| 7 | 同類のエラー二回目は必ずルールを変え、再発したら失敗するチェックを残す |
| 8 | 人への報告の骨格を固定する（結果 → 説明 → 自己検証 → 閉じられるか → 自検リスト） |
| 9 | いつ分担し、いつ相互議論し、いつバッチかを書く；多経路並行には集約産物が必要 |

**誰向けか**

Claude Code を長く使い、自分のワークフローを公開したい、agent のオーケストレーションに興味がある人、レイヤー思考を持ち帰れる。  
賑わいを見るだけの人は、アーキテクチャ、原則、早見の三節で十分。

向いていない：ワンクリックインストーラーを探す人、私の鍵とアカウントプールが欲しい人、これを Anthropic 公式ドキュメントとする人。ここにはそれらはない。
