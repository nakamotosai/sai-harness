# sai-harness

> 关于 omp / 智能体交付系统的公开笔记：证据驱动完成 · 清单永远在最后

![sai-harness：关于 omp 个人交付系统的公开笔记](assets/readme/hero.svg)

## 一句话价值

[omp（oh-my-pi）](https://omp.sh) 是一款可编程的终端智能体壳（agent shell）——哈希锚定的编辑、优化过的工具链，以及任何能跑 shell 的地方都能运行的 TUI。在它之上，我搭了一套个人交付系统：每个任务先判定——轻活跑单路径合同，重活跑多智能体流程并带一个空上下文评审（empty-context reviewer）——然后以「先拆后合」执行，用磁盘证据核验（自报「完成」无效），并以固定的 emoji 五块式骨架向人类汇报。记忆分成三层而不是一锅粥；危险操作在工具层面被拦截，而不是靠意志力；规则一改，确定性评测套件（eval suite）会在改动前后各跑一遍。全是 `AGENTS.md`、`skills/`、`agents/`、`extensions/` 和 `evals/`——这个仓库既是说明书，也是地图，也是边界。

## 为什么不一样

出厂 omp 已经能写代码、跑命令、说 MCP、开付费智能体。我没有发明第二套 harness。差距在纪律：任务怎么判定、记忆怎么分区、复杂活怎么拆怎么合、完成怎么取证，以及「我觉得没问题」算不算完成。方法是工具无关的；下面的 omp 搭建是它的一个具体、可工作的实例。

### 原则

1. **地图短，流程深。** 顶层规则只做路由；重流程进 skill。启动时读的地图保持足够小，真会被读完。
2. **完成要有证据。** 磁盘状态、命令结果、验证回执说了算。「感觉完成了」不算完成。
3. **子智能体分工。** 判定的不做质检；做质检的不写终稿；写稿的不自己审自己。空上下文评审（reviewer）审重声明。
4. **记忆分区。** 工作笔记、错题卡、知识维基、设计/主题库不是一锅。每层一个属主、一种格式。
5. **错误必须死透。** 修好产物只算一半；根因——某条规则或某道检查——也必须改，并留下防复发的哨兵。
6. **先找现成，再手搓。** 轮子搜得到，默认不重造。
7. **像同事一样说话。** 先说结果；自验证是点开、刷新、听、看——不是把一堆命令甩给你。
8. **默认拆开再回，不开会。** 独立探测/构建并行跑，结果回主控，合并落在磁盘。只有真争论或大批量同类任务才升级。
9. **只给整包。** 「做」= 整套核对过的方案，不是半吊子自选；签收票只有三个答案：照做 / 改方案 / 先搁置。

### 速查：默认 vs 我

| | 默认 omp | 本套配置 |
|--|------------|-----------|
| 定位 | 强终端编码智能体 | 个人交付 harness |
| 记忆 | 会话 + 自动笔记 | 三层：工作 · 错题卡 · 知识维基 |
| 多步任务 | 你放开了才跑 | 先判定：轻 vs 重合同 |
| 复杂并行 | 倾向一人全包 | 默认拆开再回；合并以文件落地 |
| 完成 | 自报 | 磁盘核验；轻 = 自验，重 = 独立评审 |
| 调研 | 临时搜索 | 经 search skill 分浅/深两档 |
| 出错之后 | 修同一个点 | 修产物 + 根规则 + 一道检查 |
| 对人说话 | 结构漂移 | 固定五块式骨架，清单永远最后 |
| harness 改动 | 凭感觉 | 黄金评测 基线 → 改动前后增量 |
| 体量 | 干净 shell | 约几十个 skill、六种 agent 类型、硬门禁 |

## 核心方法论

### 架构

```
You
 └─ Main control session (reads AGENTS.md map, judges, dispatches, closes out, writes back)
     ├─ Judging: light → chain/loop; heavy → multi-agent flow + empty-context reviewer
     ├─ Rules: AGENTS.md (short map) + contracts (light / heavy) + snapshot-layer rules
     ├─ Memory: working memory ↔ MaxKB-like mistake cards ↔ wiki knowledge graph
     ├─ Agents: task / scout / reviewer / designer / sonic / librarian
     ├─ Skills: entry for design, media, remote, knowledge, evolution
     ├─ Hard guards: delete-guard, path-guard (tool-level, block not warn)
     ├─ Eval: golden suite with baseline → delta on every harness change
     └─ Interfaces: browser, terminal, design/theme/library, message bridge
```

### 判定与编排（不换壳）

网上聊 agent graph 通常归结为：别全自己干，该拆就拆，拆完合起来，并盯住合起来的结果落地。

我没有换外部图引擎。我在前面写了**两份合同**和一个判定器：

| 机制 | 何时 | 保证什么 |
|---|---|---|
| **判定 / 路由** | 每个任务的第一步 | 给任务分类，决定谁干活，单线程主控 |
| **轻合同** | 小、低风险、文件少 | 带阶段依赖的任务引擎；机械自验证就够 |
| **重合同** | 其他一切 | 多智能体扇出、空上下文评审、声明过闸 |
| **拆开再回** | 独立探测/构建 | 子智能体并行跑，结果回主会话合并 |
| **合并闸** | 多路任务 | 几条并行路必须产出磁盘上的合并产物，而不是会议纪要 |
| **不开作战室** | 简单任务 | 给琐碎问题强加重型拓扑会被判定器拦住 |

你的体感：多步工作更稳、且有证据返回；小事保持单线程，而不是拉一屋子委员会。

### 完成：证据一路到底

看着完成的活，要满足这些才算：

1. **能跑 / 可观察** — 退出码通过，文件确实在声称的位置
2. **人能看明白** — 产物打开过、报完整路径、长任务报进度
3. **待办清零** — 没有未关闭的清单项（自己查一遍清单视图）
4. **沉底** — 教训/决策落到各自的事实源（维基 / 错题卡 / 模板）
5. **重活：评审通过** — 独立空上下文评审（reviewer），跨模型

崩溃要**双修**：既修这份产物，*也*修根因（一条规则或一道检查）。只把文件补上就往下走，不算数。

### 汇报骨架（对人说话）

每条消息都是一张工单。交付用固定五块式骨架，按顺序，**清单永远最后**：

| 块 | 装什么 |
|---|---|
| 🎯 一行结果 | 完成 / 结论 / 卡在哪 |
| 🧩 人话解释 | 发生了什么、怎么处理的、明确没做什么 |
| ✅ 效果与自验证 | 你会感受到什么 + 怎么确认的（点开 / 刷新 / 听了 / 看了） |
| 👉 下一步 | 能关票？明说。不够？给完整的下一步具体动作 |
| 📋 清单（永远最后） | 验证者 / 待办 / 记忆 / 维基——智能体自己的审计，不是一句「收到」 |
| （按需加） | 在哪打开、全文位置、风险、签收…… |

给选项时，每个选项都讲清（什么意思 / 什么代价 / 怎么满足你的目标）。方案整包交付，绝不自选菜单式半包。

### 记忆：三层

| 层 | 属主 | 格式 | 实际用处 |
|---|---|---|---|
| **工作记忆** | 智能体银行 | 近期 + 偏好规则 | 会话开头的上下文 |
| **错题卡** | MaxKB 式卡片 | 短教训 + 复发指纹 | 同类旧活先查它 |
| **知识图谱** | 维基 / 长文 | 每主题一个现行版 | 调研和手册放这；旧版本进历史 |

设计、主题、可复用 demo 有各自的主题库，只收真正用过的。智能体自己写回记忆；同一个问题绝不会问第二遍。

### 韧性与安全

- 危险 git、破坏性删除、直读密钥：**工具层拦截**，不是警告。
- 密钥：加密托管管线；key 永不进对话正文或日志。
- 压缩后关键规则会重新注入；地图保持小到能重读。
- 快照与归档是一等公民：任何大改之前先备份；垃圾只进一个归档根。
- 黄金评测套件在每次 harness 改动上跑基线 → 增量；出现回归 = 未完成。

### 向外看

外搜、浏览器、远端操作、定时任务：都是 harness 伸出去的触角，不是第二大脑。新实现：默认先找现成（开源优先），实在没有合适的才自写，并写清搜过什么、为何没用。

## 本仓库

**有** — 这份说明书、能力导图、hero 图，以后：脱敏模板和可抄的清单。

**没有，也永远不会放**
- API Key、Cookies、Token、账号池
- 内网地址、私有主机名、客户数据
- 连到我的生产环境的配置
- 一个「装了这个你就和我一样强」的脚本——方法可抄；你的坑和你的肌肉抄不走

## 快速开始

在官方扩展点上叠加：

| 步骤 | 做什么 |
|------|-----------|
| 1 | 写一份短而硬的 `AGENTS.md`：铁律 + 路由表；重流程住进文件 |
| 2 | 加一个判定器：决定任务用哪份合同（轻/循环 或 重/多智能体） |
| 3 | 把重复流程拆成 skill（交付、搜索、进化起步） |
| 4 | 加两个只读 agent：scout（探查）和 reviewer（审声明） |
| 5 | 用扩展焊死你最怕的错，而不是用散文 |
| 6 | 拆记忆：工作 vs 错题 vs 知识——三个文件、三个属主 |
| 7 | 完成 = 可观察证据 + 人话；自报「完成」无效 |
| 8 | 同样的错犯两次 → 改一条规则并留一道防复发的检查 |
| 9 | 修好汇报骨架（结果 → 人话 → 已验证 → 下一步 → 清单永远最后） |
| 10 | 改地图之前先跑基线评测；改完再跑 |

官方资料：
- [oh-my-pi (omp)](https://github.com/can1357/oh-my-pi) — 我基于它的终端 harness
- [omp.sh](https://omp.sh) — 使用参考
- [AGENTS.md spec](https://agents.md) — 很多 shell 都懂的地图文件格式

**给谁看** — 长期跑终端智能体、想公开/打磨自己工作流的人；这套分层（方法论、合同、执行器、数据）可搬到任何地方。只随便逛逛的访客，看架构 + 原则就够。

**不适合谁** — 一键安装党、key/账号猎手，或任何把这当某公司官方文档的人。这里一概没有。
